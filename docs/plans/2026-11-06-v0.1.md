# Agentic Coding Principles v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a public repository with an 8-stage framework, principles, templates and a tested documentation gate that the repository applies to itself.

**Architecture:** Markdown content (principles, templates) plus one standard-library Python module `checks/check_docs.py` exposing pure parsing functions and a CLI; `unittest` tests; GitHub Actions runs the tests and the gate on the repository.

**Tech Stack:** Python 3.11+ standard library, unittest, GitHub Actions.

**Spec:** `docs/design.md` (approved 06.11.2026)

## Global Constraints

- Python 3.11+, standard library only; tests with `unittest`; Windows, macOS, Linux.
- English; MIT; public `Sarpes/agentic-coding-principles`; folder: the project folder.
- Incidents are "lessons from projects built so far"; no project, company, case or domain named or described.
- `DECISIONS.md` and `AI-Agents.md` complete before every push (contract `project-docs`); entries added in the same branch as the change.
- One branch and PR per task, merge commits only, merge after Sarp's OK; handovers in private `Sarpes/agentic-coding-principles-internal`, never linked.

## Review Focus

1. CRLF line endings (Windows checkout): every rule behaves as with LF. → Task 2 test `test_crlf_same_result`.
2. UTF-8 BOM and non-ASCII text (Turkish characters) in a file: read without error, same result. → Task 2 test `test_bom_and_non_ascii`.
3. Headings inside fenced code blocks (templates and principles show examples): ignored, not counted as entries. → Task 2 test `test_fenced_examples_ignored`.
4. Near-miss field labels (`**Why**:`, `- **why:**`): reported as missing, with the expected label in the message. → Task 2 test `test_near_miss_label_named`.
5. `REQUIREMENTS.md` header and alignment rows (`|---|`): not treated as data rows. → Task 2 test `test_requirements_header_rows_skipped`.

### Task 2: Documentation gate (branch `feat/check-docs`)

**Files:** Create `checks/check_docs.py`, `tests/test_check_docs.py`, `tests/__init__.py`, `checks/__init__.py`.

**Interfaces — Produces:**
- `Problem = NamedTuple("Problem", [("file", str), ("line", int), ("message", str)])`
- `decisions_problems(text: str, file: str = "DECISIONS.md") -> list[Problem]`
- `ai_log_problems(text: str, file: str = "AI-Agents.md") -> list[Problem]`
- `requirements_problems(text: str, file: str = "REQUIREMENTS.md") -> list[Problem]`
- `check_repo(root: Path) -> list[Problem]` (missing DECISIONS.md / AI-Agents.md is a Problem at line 0; REQUIREMENTS.md checked only if present)
- `main(argv: list[str] | None = None) -> int` → 0 pass, 1 problems (each printed `FILE:LINE: message`), 2 usage error (not a directory)

Field lists and rules: identical to contract `project-docs` (7 decision fields, 5 log fields, `None: <reason>` instead of blank or bare None/TBD/TODO/-, contiguous numbering, grouped heading = one problem, sections `## Assumptions` and `## Not done (and why)`, at least one entry). Requirements: columns ID · Requirement · Decision · Test · Evidence · Status; every cell non-empty; Status in {open, met, not done}; `met` needs Test and Evidence that are not `-`.

- [ ] Step 1: Write the failing tests: per rule one firing and one look-alike case (decision missing field, bare None, `None: reason` ok, gap, duplicate, grouped heading, missing sections, zero entries; log missing field, empty field, gap; requirements empty cell, bad status, met without evidence, valid table; repo missing files; `main` exit codes 0/1/2; `test_cli_exit_1_on_broken_repo` writes a broken repo into a temporary directory and runs the CLI as a subprocess). Test inputs are built as strings in the test file, never stored as `DECISIONS.md` files plus the five Review Focus tests; each asserts the problem's line number where one exists.
- [ ] Step 2: `python -m unittest -v` → FAIL (module missing). Commit the red tests.
- [ ] Step 3: Implement; read files with `encoding="utf-8-sig"`, normalise `\r\n`; strip fenced blocks (``` … ```) by blanking their lines so line numbers stay true.
- [ ] Step 4: `python -m unittest -v` → all pass; `python checks/check_docs.py .` → exit 0 on this repo.
- [ ] Step 5: DECISIONS entry (exit codes, fenced-block rule), AI-Agents entry; commit; PR; merge after OK.
