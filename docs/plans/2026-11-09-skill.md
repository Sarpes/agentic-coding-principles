# agentic-principles skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `agentic-principles` skill: a conductor over eight stages, with gate scripts that can fail, a cited checklist, and a README, released as v0.2.0.

**Architecture:** One standalone standard-library script (`check_gates.py`) enforces what code can enforce and is copied into each project by `init_project.py`. The skill itself is a short router plus one instruction file per stage, loaded on demand, with the installed-skill mapping in one data file.

**Tech Stack:** Python 3.11+ standard library (`tomllib`, `re`, `subprocess`, `json`), `unittest`, Markdown, Claude Code plugin format.

**Spec:** `docs/design-skill.md`

## Global Constraints

- Python 3.11+, standard library only, `unittest`; Windows, macOS and Linux.
- Public repository: no project, company, client or domain named or described; no machine-specific paths. Before every push run the private-name scan.
- Every rule, gate and check has a case that must fire and a look-alike that must not; seen red before the implementation. Work one test class at a time against signature stubs that return empty results, so each check is seen failing on its own assertion and never on a bulk import error.
- `check_gates.py` prints the trust limit of design section 3 to stderr on every run.
- Exit codes 0, 1, 2; problems printed as `FILE:LINE: message`, line 0 for a whole file. Same conventions as `checks/check_docs.py`.
- Text files may carry a byte-order mark or CRLF; bytes that are not UTF-8 are a problem at their line, never a traceback.
- Companions are always named in full; their text is never copied.
- `DECISIONS.md` and `AI-Agents.md` entries in the same branch as the change; never a blank field.
- One branch per task, stacked; implementers commit, the controller pushes; merges only after the owner's OK, with merge commits.
- In a shell where Python is not on PATH, put it there first: the pre-commit hook and `tests/test_secret_gate.py` need it.

## Review Focus

1. A file map written with backslashes or spaces (`src\my file.py`) on Windows: it matches the tracked file `src/my file.py`, no false alarm. Non-ASCII file names match too. (Tasks 1, 2)
2. `check_gates.py` run in a folder that is not a git repository: exit 2 and a clear message, no traceback. (Task 1)
3. Evidence pointing outside the project (`file:../../secret.txt`): rejected as a problem, the file is not read. (Task 1)
4. `init_project.py` run on a project that already has `DECISIONS.md` or a `CLAUDE.md`: the owner's content is untouched and the marked block is added once only. (Task 6)
5. A stage flipped to `passed` when its check's document does not exist yet: reported as a missing file, not a crash. (Task 2)

`STAGES.md`: lines `Size: small|full`, `Method: normal|sub-agent`, optional `Adopted-at: N`, optional `Traits: a, b`, then `| Stage | Status | Evidence | Override |` with exactly the eight stages. Status is `open`, `passed`, `overridden`, `adopted`, or `reopened` (Stage 6 only; it does not fail a later `passed`). Evidence is comma-separated `file:<path>` and `commit:<hash>`.

`OVERRIDES.md`: `### O1. <title>` with bullets `Date`, `Stage`, `What was skipped`, `Why`, `Risk accepted`, `How to close`, `Status` (`open`/`closed`), `Closing evidence` (`-` while open), `Re-confirmed for release` (`-` or a date). Numbering gapless.

Required evidence and content per stage and size: exactly as design section 11, as a data table `REQUIRED`; the `GO-LIVE.md` requirement is added in Task 3, once traits exist. `## Reviews` is `| Task | Reviewer | Result |`. `SOURCE_EXTENSIONS = .py .ipynb .js .jsx .ts .tsx .go .rs .java .kt .swift .c .cpp .h .rb .php .cs .sh .ps1` is defined here, for the adoption check and Task 3. `templates/OVERRIDES.md` shows its format in an HTML comment only, with no `### O` heading, so a new project has no phantom override.

`ATTACKS.md`: `| ID | Attack | Rung | Drafted by |`, ids `ATK-1`.., Rung `3` or `5` or `-`; minimum 3 rows on Small, 5 on Full; the `(EXAMPLE)` marker fails. It is a separate file because `requirements_problems` in `check_docs.py` reads every table row in `REQUIREMENTS.md`.

Manifests: `requirements*.txt`, `pyproject.toml` (`project.dependencies`, `project.optional-dependencies`), `package.json` at any depth outside `node_modules` (`dependencies`, `devDependencies`). Python names normalised lower-case with runs of `-_.` collapsed. Unreadable: `go.mod`, `Cargo.toml`, `Gemfile`, `pom.xml`, `build.gradle`, `composer.json`, `environment.yml`, `setup.py`, `Pipfile`, and any `pyproject.toml` that has `tool.poetry` or `dependency-groups`.

Timing in `check_project`: `ATTACKS.md` binds at Stage 0 `passed`; `## Tests` at Stage 4; the other sections at Stage 5.

Explain-back binds at Stage 5 `passed` (every topic answered); the full round at Stage 6 (minimum 3 on Small; on Full the larger of 3 and the component count). Stage 5 `overridden` skips explain-back and go-live, but not override re-confirmation.
